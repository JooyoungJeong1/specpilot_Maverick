# 설계서 읽는 법
- 한 화면은 보통 머리글, 화면 이미지, Description, Action/Event로 이루어진다.
  - 머리글: Depth(메뉴 묶음), 화면명, 화면 ID, 작성자
  - 화면 이미지의 숫자 마커(1, 2, 3 …)는 같은 번호의 Description 항목을, 알파벳 마커(A, B …)는 같은 글자의 Action/Event 항목을 가리킨다. 마커가 붙은 요소가 그 항목의 대상이다. 입력란이나 버튼뿐 아니라 화면 위쪽의 이동 링크(상단 경로 표시 등)나 입력란 옆 아이콘에도 마커가 붙을 수 있다.
  - Description 0번은 화면 개요다.
- 같은 화면 ID가 여러 페이지에 나오고 설명 없이 이미지만 있는 페이지는, 오류 메시지나 팝업이 나타난 모습을 보여 주는 상태 화면이다.
- 팝업도 별도 화면 ID를 가질 수 있다. 팝업 화면의 이미지에는 팝업을 연 부모 화면이 어둡게 깔려 있다. 팝업 창 안의 제목, 문구, 버튼만 그 팝업 화면의 요소이고, 뒤에 깔린 화면의 요소는 부모 화면의 것이다.
- 머리글 값은 텍스트로 추출되지 않고 이미지에만 있을 수 있으니 페이지 이미지를 함께 본다.
- 텍스트 추출은 띄어쓰기가 빠지거나 줄이 끊길 수 있다 (예: "올바르지않습니다"). 띄어쓰기는 다음 단계에서 비교하지 않으므로 맞추려고 하지 않는다. 문구는 글자만 정확히 옮긴다.
- 설계서 형식이 이와 다르면, 같은 역할을 하는 부분(요소 설명, 조작 결과, 화면 그림)을 찾아 대응시킨다.
